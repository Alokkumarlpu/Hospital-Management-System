# Phase 3 Management API

All management endpoints require the Phase 2 HTTP-only session cookie. Responses use JSON and return `{ success, ... }`. Invalid request data returns `400`; missing authentication returns `401`; insufficient role returns `403`; missing records return `404`; duplicate identifiers return `409`.

## Patients

| Method | Path | Roles | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/patients` | admin, front_desk | Register patient |
| `GET` | `/api/patients?search=&page=1&limit=10&isActive=true` | all roles | Search and paginate |
| `GET` | `/api/patients/:id` | all roles | View patient |
| `PUT` | `/api/patients/:id` | admin, front_desk | Update permitted fields |
| `PATCH` | `/api/patients/:id/status` | admin, front_desk | Activate/deactivate |

Example:

```json
{
  "name": "Synthetic Patient",
  "dateOfBirth": "1990-01-01",
  "gender": "female",
  "phone": "+1 555 0100",
  "email": "patient@example.test",
  "address": "Synthetic address",
  "bloodGroup": "O+",
  "emergencyContact": {
    "name": "Synthetic Contact",
    "relationship": "friend",
    "phone": "+1 555 0101"
  }
}
```

Patient IDs are generated by the API. Clinician responses omit address and emergency contact information.

## Doctors

| Method | Path | Roles | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/doctors` | admin | Add doctor |
| `GET` | `/api/doctors?search=&page=1&limit=10&departmentId=` | all roles | Search and paginate |
| `GET` | `/api/doctors/:id` | all roles | View doctor profile |
| `PUT` | `/api/doctors/:id` | admin | Update doctor |
| `PATCH` | `/api/doctors/:id/status` | admin | Activate/deactivate |

Doctor creation requires an active department. An optional `userId` must reference an active clinician account. Doctor IDs are generated by the API.

## Departments

| Method | Path | Roles | Purpose |
| --- | --- | --- | --- |
| `POST` | `/api/departments` | admin | Create department |
| `GET` | `/api/departments?search=&page=1&limit=10&isActive=` | all roles | Search and paginate |
| `GET` | `/api/departments/:id` | all roles | View department and assigned doctors |
| `PUT` | `/api/departments/:id` | admin | Update department |
| `PATCH` | `/api/departments/:id/status` | admin | Activate/deactivate |

Department names and codes are unique. A department with active doctors cannot be deactivated. Historical references are retained; no delete endpoint exists.

## Audit logging

Patient creation, updates, activation, and deactivation write `AuditLog` records containing the authenticated user, action, entity type, entity ID, and changed-field metadata. Doctor and department mutations are also logged.

## Role matrix

| Capability | Admin | Front desk | Clinician |
| --- | --- | --- | --- |
| Register/update patients | Yes | Yes | No |
| Read patients | Full | Full | Limited clinical directory fields |
| Manage doctors | Yes | No | No |
| Read doctor directory | Yes | Yes | Yes |
| Manage departments | Yes | No | No |
| Read department directory | Yes | Yes | Yes |
